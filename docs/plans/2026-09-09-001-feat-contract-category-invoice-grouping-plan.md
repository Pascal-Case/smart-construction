# 계약 구분별 거래명세표와 대표 출력 품목

## 확정 요구사항

- 계약 구분은 코드가 자동 생성되는 관리자용 마스터로 관리한다. 초기값은 `스마트건설안전`, `근로자안전보건`, `스마트안전패드`이며 가나다순으로 표시한다.
- 계약과 직접·조정 매출은 계약 구분을 반드시 가진다. 계약 자동 매출은 계약 구분을 원장에 복사한다.
- 월마감은 기존처럼 현장·월 단위로 한 번 수행하되, 마감 snapshot에 계약 구분과 대표 출력 품목을 고정한다.
- 최초 발행은 한 마감 회차의 매출을 계약 구분별 거래명세표로 나누어 한 transaction에서 발행한다. 구분별 매출이 없으면 문서를 만들지 않는다.
- 계약 구분은 발행 관리 목록에 표시하고 인쇄 양식에는 추가하지 않는다. 공급자, 수신처, 메모, 템플릿, 표시 방식은 함께 발행되는 문서에 동일하게 적용한다.
- 품목 마스터는 선택적인 대표 출력 품목을 가진다. 신규 설정은 활성 품목만 대상으로 하며 자기 참조, 연쇄 참조, 순환 참조를 허용하지 않는다.
- `동일 품목 합산`에서 대표 품목으로 연결된 원장 행은 대표 품목명과 공급가액 합계로 표시한다. 규격·수량·단위·단가가 서로 다르면 해당 계산 열을 비운다. `원장 건별 표시`는 원래 품목을 유지한다.
- 초기 데이터는 `ITEM-0024 사진 분석 개발비용`을 `ITEM-0023 플랫폼 사용료`로 연결한다.
- 세액은 출력 최종 행별 공급가액의 10%를 반올림해 합산하며 인쇄 문구 `원 / VAT 별도`를 유지한다.
- 기존 계약명이 세 초기값 이외이면 migration을 중단한다. 운영 migration 직전에 DB 온라인 백업과 무결성 검사를 수행한다.

## 검증 기준

- 기존 계약·매출 건수와 금액을 보존하고 모든 기존 계약 및 계약 매출에 구분이 채워진다.
- 한 현장·월의 서로 다른 계약 구분이 별도 문서가 되며 각 원장 연결은 정확히 한 문서만 가리킨다.
- 대표 품목 합산과 건별 표시 결과, 이질적인 계산 열 비움, 마감 snapshot 고정을 테스트한다.
- 대체 발행도 최신 마감 snapshot을 사용해 계약 구분별 문서를 만들고 기존 유효본을 원자적으로 대체한다.
