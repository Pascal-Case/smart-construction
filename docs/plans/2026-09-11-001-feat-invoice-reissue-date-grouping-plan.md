# 거래명세표 발행일·자동 그룹 재발행 계획

## 결정된 범위

- 관리자와 매니저는 발행 이력의 현재 유효한 거래명세표에서 언제든지 `재발행`을 시작할 수 있다.
- 재발행은 항상 새 발행번호를 만든다. 기존 문서는 삭제하지 않고 `SUPERSEDED`로 바꾸며 새 문서와 연결한다.
- 사용자가 바꿀 수 있는 값은 새 발행일과 재발행 사유뿐이다. 표시 방식, 템플릿, 메모, 수신처, 품목, 수량, 단가, 금액, 부가세는 기존 snapshot을 사용한다.
- 그룹은 현장·계약 구분·발행일 기준으로 자동 계산한다. 같은 날짜로 이동한 기존 문서는 하나로 합치고, 발행일이 다른 문서는 계속 별도 문서로 둔다.
- 여러 기존 문서가 하나로 합쳐지고 문서 snapshot이 다르면, 사용자가 시작한 선택 원본 문서의 수신처·공급자·표시 방식·템플릿·메모 snapshot을 적용하고 미리보기에서 알린다.
- 1:N 또는 N:1 변화가 발생하면 영향받는 기존 문서만 함께 대체한다. 다른 발행일의 문서는 그대로 유지한다.
- 미리보기에는 영향받는 기존 문서 수, 새 문서 수, 발행일·그룹·금액을 표시한다.
- 확정 시 새 문서 생성, 현재 매출 연결 이동, 기존 문서 대체 상태 변경, 감사 기록을 하나의 트랜잭션으로 처리한다. 실패하면 전체를 롤백한다.
- 재발행 사유는 필수이며 감사 기록에 실행자, 시각, 이전 문서, 새 문서, 발행일·그룹, 사유를 남긴다.

## 제외 범위

- 도장, 업체 전달, 인쇄 후 처리 상태와 후속 업무는 다루지 않는다.
- 별도 마감 취소·되돌리기 화면은 추가하지 않는다.
