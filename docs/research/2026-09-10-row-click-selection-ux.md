# 목록 행 클릭 선택 UX 조사

## 조사 질문

업무 화면의 목록에서 체크박스만 선택 수단으로 제공하는 경우, 행의 빈 영역을 클릭해도 같은 선택 동작을 수행하도록 개선할 가치가 있는 화면을 찾는다. 특히 최근 수정 중인 거래명세표 발행 화면을 우선 검토한다.

## 결론

행 클릭 선택은 모든 목록에 일괄 적용할 기능이 아니다. **이미 체크박스 선택이 있고, 선택 결과가 일괄 작업으로 이어지는 목록**에만 적용하는 것이 적절하다.

우선 적용 대상은 다음 세 화면이다.

1. **거래명세표 발행 대기**: P0
2. **계약 매출 생성 다이얼로그**: P0
3. **월마감**: P1

그 다음으로 **매출 원장**의 작성 중 계약 매출에 한해 P1로 검토한다. 현재 실제 데이터는 확정 매출만 있어 체크박스가 비활성화되어 있으므로, 선택 가능한 작성 중 상태에서만 효과를 확인할 수 있다.

## 평가 기준

- 행 선택이 실제 업무 명령으로 연결되는가
- 한 행에 표시되는 정보가 많아 체크박스까지 이동하는 비용이 큰가
- 행 안에 날짜 입력, 버튼, 링크, 펼치기 등 다른 조작 요소가 있는가
- 선택 불가 상태를 행 클릭에도 동일하게 적용할 수 있는가
- 체크박스를 유지해 키보드·스크린 리더 사용성을 보존할 수 있는가

## 우선순위 매트릭스

| P0 | 거래명세표 발행 대기 | 후보 품목별 체크박스, 전체 선택 | `selectable`인 신규·대체 후보 행 | 품목 행이 많고 선택 후 문서 발행·그룹 분리가 바로 이어진다. |

| P1 | 매출 원장 | 작성 중 계약 매출만 체크박스 선택 | 계약 출처이면서 `DRAFT`인 행 | 일괄 확정 대상에만 의미가 있다. 확정·직접·조정·취소 행은 제외해야 한다. |

| 제외 | 계약 구분·사용자 관리 | 행 액션 또는 인라인 폼 | 적용하지 않음 | 사용자 관리의 체크박스는 선택이 아니라 사용 여부 변경이다. |
| 제외 | 감사 로그, 이관 이력, 거래명세표 발행 이력 | 읽기 전용 목록 | 적용하지 않음 | 행 선택으로 이어지는 후속 일괄 작업이 없다. |

## 화면별 근거와 권장안

### 1. 거래명세표 발행 대기: 최우선

현재 발행 후보는 행마다 `selectable` 여부를 기준으로 체크박스를 활성화하고, 선택된 후보를 발행 미리보기로 전달한다. 선택 품목별 개별 분리와 자동 묶음 복귀도 선택된 신규 품목을 대상으로 동작한다. [invoice-manager.tsx:275-307](../../src/components/invoices/invoice-manager.tsx#L275-L307) [invoice-manager.tsx:556-585](../../src/components/invoices/invoice-manager.tsx#L556-L585)

실제 화면에서도 8개 후보와 4개 자동 그룹이 표시되고, 각 품목 행에 체크박스와 개별 발행일 입력이 함께 있다. 이 구조에서는 품목명·현장·계약 구분을 확인한 뒤 행의 빈 영역을 클릭하는 것이 작은 체크박스를 직접 누르는 것보다 자연스럽다.

권장 동작:

- 신규 또는 대체 후보 중 `row.selectable === true`인 행만 행 클릭으로 선택·해제한다.
- 체크박스는 그대로 유지한다. 행 클릭은 편의 동작이고, 키보드 접근의 기본 수단은 체크박스로 둔다.
- 발행일 `input`을 클릭하거나 변경할 때는 선택 상태가 바뀌지 않아야 한다.
- `BLOCKED` 행과 비선택 행에는 포인터 커서·선택 배경·행 클릭을 적용하지 않는다.
- 선택 품목별 개별 분리, 자동 묶음 복귀, 그룹별 선택 건수, 발행 예상 장수는 기존 선택 상태를 그대로 사용한다.
- `data-state="selected"`와 `aria-selected`를 행에 반영하면 공통 테이블의 선택 배경 스타일을 재사용할 수 있다. 공통 `TableRow`는 이미 `data-[state=selected]` 스타일을 지원한다. [table.tsx:45-54](../../src/components/ui/table.tsx#L45-L54)

이 화면의 핵심은 **행 클릭이 문서 그룹을 직접 바꾸는 것이 아니라 후보 선택 상태만 바꾸는 것**이다. 발행일이나 품목별 분리 규칙은 현재 구현된 선택·미리보기 계산을 그대로 통과해야 한다.

### 2. 계약 매출 생성: 최우선

계약 매출 생성 다이얼로그의 초기 후보 표는 계약번호, 현장, 계약명, 처리 대기일을 표시하고 체크박스로 계약을 선택한다. 페이지 전체 선택과 검색 결과 최대 100건 선택도 같은 `selectedIds` 상태를 사용한다. [contract-revenue-generation-dialog.tsx:214-215](../../src/components/revenues/contract-revenue-generation-dialog.tsx#L214-L215)

이 표의 후보 행에는 날짜 입력이나 행별 관리 버튼이 없다. 따라서 행의 어느 빈 영역을 눌러도 동일 계약을 선택·해제하는 방식이 가장 안전한 적용 사례다.

권장 동작:

- 초기 `candidates.rows` 표에만 적용한다.
- 행 클릭은 반드시 기존 `toggleOneSelection`을 호출해 최대 100건 제한과 경고 동작을 공유한다.
- 헤더 체크박스, 현재 페이지 전체 선택, 검색 결과 최대 100건 선택은 유지한다.
- 미리보기 결과인 `BatchResponsePanel`의 결과 행에는 적용하지 않는다. 해당 행은 상세 펼치기 버튼을 가진 결과 목록이며 선택 목록이 아니다.

### 3. 월마감: 조건부 적용

월마감은 선택된 현장으로 `선택 마감`을 실행하며, 닫히지 않은 현장만 `selectedRows`에 포함한다. 체크박스도 `closed || !canClose`이면 비활성화된다. [month-close-control-room.tsx:94-101](../../src/components/reports/month-close-control-room.tsx#L94-L101) [month-close-control-room.tsx:202-230](../../src/components/reports/month-close-control-room.tsx#L202-L230)

실제 화면에는 현재 두 현장이 모두 마감 완료라 체크박스와 일괄 마감 버튼이 비활성화되어 있다. 따라서 행 클릭은 열린 현장 데이터가 있는 경우에만 표시·동작해야 한다.

주의할 내부 조작:

- 예외 카드의 `검토` 버튼
- 마감 되돌리기 버튼
- 거래명세표 발행으로 이동하는 링크형 버튼
- 마감 이력의 `details` 펼치기

이 요소들의 클릭은 행 선택으로 전파되면 안 된다. 특히 관리 열은 행 클릭의 대상에서 제외하거나, 이벤트 대상이 버튼·링크·details 내부인지 검사해야 한다.

### 4. 매출 원장: 작성 중 계약 매출에 한정

매출 원장의 일괄 확정 상태는 `selectedContractRevenueIds`로 관리되고, 선택 대상은 계약 출처이면서 `DRAFT`인 행으로 한정된다. 헤더 체크박스도 해당 조건을 만족하는 현재 페이지 행이 있을 때만 활성화된다. [revenue-manager.tsx:32-45](../../src/components/revenues/revenue-manager.tsx#L32-L45) [revenue-manager.tsx:62-71](../../src/components/revenues/revenue-manager.tsx#L62-L71)

실제 화면의 9개 행은 모두 확정 상태라 현재 헤더 체크박스가 비활성화되어 있다. 이 화면에서 전체 행을 클릭 가능하게 만들면 확정·직접·조정·취소 행까지 일괄 확정 대상으로 오인할 수 있으므로, 작성 중 계약 매출 행에만 선택 affordance를 제공해야 한다.

행 내부에 확정·취소·수정 버튼이 있으므로 관리 열과 버튼·링크·입력 요소는 행 선택에서 제외한다.

## 적용하지 않는 화면

- **계약 관리**: 목록 행은 계약 상세 편집을 위한 `수정` 버튼만 가진다. 선택 후 실행되는 일괄 작업이 없으므로 행 클릭 선택을 추가할 이유가 없다. [contract-manager.tsx:49](../../src/components/contracts/contract-manager.tsx#L49)
- **현장·품목 마스터**: 목록은 `수정` 버튼으로 편집한다. 가져오기 미리보기의 `allOrNothing` 체크박스는 행 선택이 아니라 저장 정책 옵션이다. [master-manager.tsx:108-109](../../src/components/masters/master-manager.tsx#L108-L109) [master-manager.tsx:179-181](../../src/components/masters/master-manager.tsx#L179-L181)
- **계약 구분 관리**: 각 행에 명칭 수정과 중지·재사용 액션이 있다. [contract-category-manager.tsx:51-52](../../src/components/contract-categories/contract-category-manager.tsx#L51-L52)
- **사용자 관리**: 행 전체가 이름·역할·사용 여부·비밀번호를 수정하는 인라인 폼이다. 행 클릭은 입력 중인 값을 방해할 수 있다. [users-manager.tsx:45](../../src/components/users/users-manager.tsx#L45)
- **월별 현황**: 집계·상세 표를 조회하는 화면이며 선택 후 일괄 명령이 없다. [monthly-report.tsx:245-292](../../src/components/reports/monthly-report.tsx#L245-L292) [monthly-report.tsx:465-505](../../src/components/reports/monthly-report.tsx#L465-L505)
- **감사 로그·이관 이력**: 일괄 선택이나 선택 후 명령이 없는 읽기 전용 이력이다. [audit/page.tsx:22](../../src/app/(main)/settings/audit/page.tsx#L22) [migration-manager.tsx:77-81](../../src/components/migration/migration-manager.tsx#L77-L81)
- **거래명세표 발행 이력**: 재출력·대체 발행은 행 선택이 아니라 행별 관리 액션으로 보는 것이 명확하다. 발행 대기 후보와 같은 선택 동작을 이력에 확장하지 않는다. [invoice-manager.tsx:603-604](../../src/components/invoices/invoice-manager.tsx#L603-L604)
- **템플릿 관리**: 템플릿 편집 화면의 표는 설정·편집 목적이며 목록 선택 작업이 아니다. [template-editor.tsx](../../src/components/invoices/template-editor.tsx)

## 공통 상호작용 규칙

1. **체크박스 유지**: 행 클릭만 남기지 않는다. 체크박스는 키보드와 보조기기에서 명확한 선택 컨트롤이다.
2. **선택 가능 행만 반응**: disabled 조건과 행 클릭 조건을 같은 도메인 판정 함수에서 파생한다.
3. **중첩 조작 보호**: `input`, `button`, `a`, `select`, `textarea`, `details` 등 조작 요소에서 시작한 이벤트는 행 선택으로 처리하지 않는다.
4. **시각적 피드백**: 선택 가능 행에만 `cursor-pointer`와 hover 상태를 주고, 선택된 행에는 `aria-selected`와 `data-state="selected"`를 함께 반영한다.
5. **행 클릭은 선택만 수행**: 행 클릭으로 편집·이동·미리보기를 동시에 수행하지 않는다. 행 내부 관리 버튼의 책임을 유지한다.
6. **현재 페이지 전체 선택과 동일한 상태 사용**: 행 클릭, 행 체크박스, 헤더 전체 선택이 서로 다른 선택 모델을 만들지 않도록 기존 toggle 함수를 공유한다.

## 권장 적용 순서

1. 거래명세표 발행 대기와 계약 매출 생성 다이얼로그에 먼저 적용한다.
2. 체크박스 클릭이 한 번만 토글되는지, 거래명세표의 발행일 입력이 선택을 바꾸지 않는지 검증한다.
3. 월마감의 열린 현장과 예외·관리 액션 전파를 검증한다.
4. 작성 중 계약 매출 데이터가 있는 상태에서 매출 원장에 적용하고, 확정·직접·조정·취소 행이 반응하지 않는지 확인한다.

## 검증 시나리오

- 선택 가능한 행의 빈 영역 클릭: 체크박스와 요약 건수가 한 번 토글된다.
- 체크박스 직접 클릭: 한 번만 토글된다.
- 거래명세표 발행일 입력 클릭·변경: 선택 상태는 유지된다.
- 비선택·차단·마감 완료·확정 행 클릭: 아무 동작도 하지 않는다.
- 행 내부의 검토, 수정, 확정, 취소, 되돌리기, 발행 이동, 상세 펼치기 클릭: 해당 액션만 실행된다.
- 헤더 전체 선택과 행 클릭을 섞어 사용: 중복 선택이나 누락이 없다.
- 거래명세표의 품목별 개별 분리·자동 묶음 복귀 후 그룹 수와 발행 예상 장수가 기존 규칙과 일치한다.
- 계약 매출 생성에서 100건 초과 선택 시 기존 제한과 경고가 유지된다.
- 키보드로 체크박스를 조작할 때 행 클릭 도입 전과 동일하게 선택할 수 있다.
