Grounding Context

Codebase Context. Phase 1~11의 기본 업무와 자동 검증은 완료됐고, 최근 변경으로 월별 현황에서의 바로 등록, 조치형 대시보드, 거래명세표 템플릿, 대체발행까지 들어왔습니다. 현장은 이제 계약·매출·명세표를 생성하고 변경 이력을 보존할 수 있습니다.

가장 큰 내부 공백은 구현계획의 업무 규칙과 실제 화면 사이에 있습니다. IMPLEMENTATION_PLAN.md:444-449는 현장 단위 또는 전체 현장의 월마감, 단가·0원·예외 경고, 마감 후 수정 통제를 명시하지만, 현재 revenue-manager.tsx:46의 자동 생성기는 계약 하나씩 preview/generate하고 확정도 행 단위입니다. 즉 데이터 규칙은 갖춰졌지만 “한 달을 닫는 작업”은 아직 제품 단위가 아닙니다.

두 번째 공백은 발행 이후입니다. RevenueStatus는 작성 중·확정·취소, InvoiceStatus는 발행·대체까지만 표현하며 지급기일, 입금, 잔액, 연체 상태가 없습니다. 외부 제품의 표준 패턴도 이 지점을 강조합니다. QuickBooks의 A/R Aging은 미수 잔액과 연체 기간을 기본 운영 단위로 보고, Autodesk Cost Management는 계약·지급·예측을 함께 연결합니다.

세 번째 기회는 이미 저장 중인 매출·원가 snapshot입니다. 월별 이익과 매출 원장 합계에는 활용되지만 계약 목록은 총 매출만 보여주므로, 실제·예정·잔여 이익과 종료 위험을 판단하기 어렵습니다. Autodesk의 Forecast도 같은 예산 데이터를 실제·계획·예측으로 나누는 방식을 취합니다. 이는 외부 기능을 그대로 복제하자는 뜻이 아니라, 현재 데이터가 이미 경영 판단으로 확장될 준비가 됐다는 근거입니다.

마지막으로 운영은 여전히 사람의 기억에 많이 의존합니다. 운영 가이드의 서버 PC·IP·백업 위치는 미정이고, health·백업·task·disk·로그·복구 훈련을 매일/매주/분기마다 수동 확인합니다. 현재 health API는 DB 연결과 SELECT 1만 확인합니다. 내부 학습 문서인 docs/solutions/는 존재하지 않아 재사용할 별도 학습은 없었습니다.

검증 메모: 저장소 지침에 따라 별도 서브에이전트 없이 메인 스레드에서 모든 근거를 재검증했습니다. 특히 월마감 규칙의 실제 줄과 수금 모델의 부재를 현재 schema·source에서 다시 확인했습니다.
