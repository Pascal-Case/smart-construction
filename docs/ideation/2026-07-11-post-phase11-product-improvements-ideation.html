Evidence

Grounding Context

Codebase Context. 현재 대시보드는 연간 KPI·차트·링크 없는 최근 활동을 보여줍니다. 반면 월별 화면에는 이미 작성 중 건수와 0원 건수 집계가 있고, 거래명세표 화면에는 확정 후 미발행 후보가 있습니다. 필요한 데이터는 존재하지만 첫 화면에서 조치 순서로 연결되지 않습니다.

월별 현황의 셀 상세는 이미 특정 siteId와 month, 사용자 수정 권한을 알고 있지만 현재 가능한 후속 행동은 메모 입력뿐입니다. 매출 원장에는 직접 매출 등록 폼이 있으므로 이를 재사용 가능한 화면으로 분리하면 새 저장 규칙 없이 월별 상세에서 바로 매출을 등록하고 같은 셀을 갱신할 수 있습니다.

계약·매출·월별·명세표 필터는 대부분 컴포넌트 로컬 상태로 유지됩니다. 새로고침·뒤로가기·링크 공유 시 조회 맥락이 사라져 대시보드 카드가 정확한 작업 목록으로 이어지기 어렵습니다. 사이드바도 현재 위치 표시와 접힘 상태 보존이 없고, 작은 화면에서는 주요 업무 내비게이션이 숨겨집니다.

스마트 입력의 1차 범위인 현장·품목 추천, 키보드 선택, 한국어 IME 대응, 날짜·단가 분석, 등록 폼 적용과 직접 등록은 구현·자동 검증되었습니다. 추가 다건 인박스는 실제 사용 피드백 없이 확장하기보다, Phase 11 수동 인수와 현장 사용 결과를 먼저 모으는 편이 안전합니다.

외부 사례도 같은 방향을 지지합니다. Autodesk Construction IQ는 비용·일정 위험이 큰 항목을 우선 처리하게 하고, Linear Custom Views와 SAP의 worklist tile은 필터된 작업 목록을 저장해 홈에서 같은 맥락으로 되돌아가게 합니다. Metabase의 result alert처럼 예외가 있을 때만 전면에 드러내는 방식도 대시보드 소음을 줄입니다.

현재 제약: Phase 11 수동 인수는 2026-07-13 예정입니다. 그 결과가 나오기 전에는 데이터 쓰기 흐름을 넓히지 않고, 다음 작업은 읽기 중심 UI와 이동 맥락 개선으로 시작하는 것이 적절합니다.

1

월별 현황에서 현장·월 매출 바로 등록

월별 검토 흐름신뢰도 98%복잡도 Medium

Description: 현장×월 셀의 상세 대화상자에 권한이 있는 사용자에게 “이 현장·월 매출 등록” 버튼을 제공합니다. 버튼을 누르면 상세를 닫고 기존 직접 매출 등록 폼을 같은 월별 화면에서 열며, 현장과 대상월을 미리 채웁니다. 귀속일의 정확한 일자는 자동 추정하지 않고 해당 월 범위 안에서 사용자가 확인하게 하며, 저장 후 원래 셀을 즉시 갱신합니다.

현장×월 셀 선택상세·누락 확인맥락이 채워진 매출 등록같은 셀 즉시 갱신
Axis
월별 검토 흐름
Basis
direct: 사용자가 이 흐름을 직접 요청했습니다. 코드상 월별 상세는 siteId·cell.month·canEdit를 이미 보유하고, 매출 원장에는 검증된 직접 등록 폼과 POST API가 존재합니다.
Rationale
누락을 발견한 화면에서 바로 보완하게 해 이동·재검색·현장 재선택을 없애며, 기존 매출 저장 규칙을 그대로 재사용합니다.
Downsides
월만으로 정확한 귀속일을 추정하면 잘못된 날짜가 저장될 수 있습니다. 중첩 대화상자를 피하고, 현장·월 맥락과 귀속일 확인을 명확히 보여줘야 합니다.
Best first cut
상세 하단에 권한 기반 등록 버튼을 추가하고, 재사용 등록 폼에 현장과 대상월을 전달합니다. 귀속일은 해당 월 범위로 제한해 사용자가 일자를 선택하고, 저장 후 월별 데이터를 다시 불러옵니다.
2

오늘의 조치 데스크

대시보드·조치 큐신뢰도 96%복잡도 Medium

Description: 대시보드 상단에 “작성 중 매출”, “0원 매출”, “확정 후 미발행” 세 가지 읽기 전용 조치 카드를 둡니다. 각 카드는 건수·영향 금액·가장 오래된 항목을 보여주고, 클릭하면 해당 조건이 적용된 매출 원장 또는 거래명세표 후보 화면으로 이동합니다. 정상일 때는 완료 메시지만 보여줘 대시보드를 예외 중심으로 조용하게 유지합니다.

기존 상태·집계건수·금액·경과일우선 조치 카드필터된 작업 목록
Axis
대시보드와 조치 큐
Basis
direct: 월별 집계가 이미 작성 중·0원 건수를 계산하고, 명세표 후보 API가 확정·미발행 매출을 반환합니다. 대시보드는 현재 연간 합계와 최근 로그만 노출합니다. external: Autodesk는 영향이 큰 위험의 우선 처리를, Metabase는 결과가 있을 때만 드러나는 예외 패턴을 사용합니다.
Rationale
핵심 도메인이나 저장 규칙을 바꾸지 않고도 사용자가 여러 화면을 순회하며 누락을 찾는 시간을 줄일 수 있습니다.
Downsides
URL 필터가 먼저 연결되지 않으면 카드는 단순 통계에 그칩니다. 1차 범위에서 모호한 종합 점수나 AI 우선순위는 넣지 않아야 합니다.
Best first cut
URL 업무 렌즈 기반을 먼저 적용한 뒤, 작성 중·0원·미발행 세 카드와 딥링크만 추가.
3

URL 업무 렌즈: 조회 맥락 보존과 공유

목록·조회 맥락신뢰도 95%복잡도 Medium

Description: 계약·매출·월별·명세표의 필터와 페이지를 URL search params에 동기화합니다. 새로고침·뒤로가기 후에도 같은 결과가 유지되고, “현재 조건 링크 복사”로 동료에게 같은 목록을 전달할 수 있습니다. 이후 대시보드 조치 카드가 이 URL을 사용해 정확한 작업 목록으로 이동합니다.

필터·기간·페이지URL에 조회 상태 반영새로고침·공유같은 작업 맥락 복원
Axis
목록과 조회 맥락
Basis
direct: 네 주요 업무 화면이 조회용 URLSearchParams를 만들지만 필터 자체는 useState에만 저장하며 useSearchParams를 사용하지 않습니다. external: Linear과 SAP는 필터된 동적 뷰를 저장하거나 홈 타일로 되돌아가는 운영 패턴을 제공합니다.
Rationale
작은 기반 변경이 대시보드 딥링크, 공유, 뒤로가기, 향후 저장 뷰까지 여러 개선의 공통 토대가 됩니다.
Downsides
모든 화면을 한 번에 바꾸면 회귀 범위가 넓습니다. 지원 파라미터와 기본값 제거 규칙을 화면별로 통일해야 합니다.
Best first cut
매출 원장의 기간·현장·출처·상태 필터부터 URL과 동기화하고 링크 복사를 제공.
4

내비게이션 연속성: 현재 위치·접힘 보존·작은 화면 메뉴

내비게이션·화면 연속성신뢰도 86%복잡도 Low

Description: 사이드바에서 현재 화면을 명확히 강조하고, 접힘 상태를 브라우저에 보존하며, 작은 화면에서도 열 수 있는 업무 메뉴를 제공합니다. 목록 상세나 대화상자를 닫은 뒤에는 직전의 조회·스크롤 맥락으로 복귀하도록 화면 연속성을 다듬습니다.

Axis
내비게이션과 화면 연속성
Basis
direct: 현재 AppShell은 pathname 기반 활성 상태가 없고 접힘 상태가 useState에만 있으며, md 미만에서는 aside 전체가 숨겨집니다.
Rationale
도메인 로직을 건드리지 않는 작은 작업으로 사용자의 위치 인지와 반복 이동의 안정감을 높일 수 있습니다.
Downsides
사내 Windows PC 중심이라 모바일 메뉴의 사용 빈도는 불확실합니다. 데스크톱 활성 표시와 상태 보존을 먼저 검증해야 합니다.
Best first cut
현재 메뉴 강조와 접힘 상태 보존부터 적용하고, 작은 화면 메뉴는 Phase 11 사용 환경에서 필요성을 확인한 뒤 포함.
5

Git staging식 안전 일괄 처리

목록·일괄 처리신뢰도 88%복잡도 High

Description: 여러 매출을 선택해 즉시 확정·취소하는 대신 먼저 작업 바구니에 담고, 변경 전후 diff와 `처리 가능·이미 변경됨·보호됨·오류` 분류를 확인한 후 한 번에 실행합니다. commit 직전에 각 행의 version을 재검증해 충돌 행만 제외하거나 전체 취소할 수 있게 합니다.

Axis
월별 검토 흐름
Basis
direct: import의 preview→commit, 명세표의 ID 배열 선택, 레코드별 version 충돌 제어가 이미 있어 공통 안전 계약을 만들 기반이 있습니다.
Rationale
월말 수십 건의 반복 클릭을 줄이면서 “대량 작업은 위험하다”는 운영 불안을 낮춥니다.
Downsides
데이터 쓰기·권한·동시성 범위를 넓히므로 Phase 11 인수 직후의 첫 작업으로는 위험합니다. 읽기 중심 개선에서 실제 반복 클릭 수요가 확인된 뒤 진행해야 합니다.
Best first cut
후속 단계에서 매출 다중 확정만 지원하고, 실행 전 preview에 충돌·보호·불가 사유를 표시.

Rejection Summary

#검토한 아이디어제외·통합 이유
1스마트 입력 2.0 전체 확장현장·품목 추천, 키보드·IME, 날짜·단가 분석과 직접 등록까지 1차 범위가 구현됨. 다건 인박스·학습형 별칭은 실제 사용 피드백 후 재평가.
2모바일 현장 포착 루프모바일 입력 빈도와 오프라인 수요의 직접 근거가 없어 투자 우선순위 보류.
3전역 업무 실행기현재 제품 규모에서는 URL 업무 렌즈와 내비게이션 연속성이 더 단순하고 근거가 강함.
4차트 없는 3문장 대시보드오늘의 조치 데스크에 통합. “3문장”은 카피 실험이지 독립 제품 방향은 아님.
5결과형 외부 알림오늘의 조치 데스크에 앱 내 카드로 통합. 이메일·메신저 알림은 운영 복잡도 대비 이른 단계.
6완전한 월마감 워크벤치쓰기 상태와 일괄 확정을 포함하면 범위가 큼. 먼저 읽기 전용 월별 예외 검토 보드로 가치를 검증.
7개인·팀 저장 뷰URL 업무 렌즈의 후속 확장으로 보류. 먼저 URL 복원·공유가 실제로 반복 사용되는지 확인.
8최근 활동 대신 중단한 곳부터가치는 있으나 사용자별 작업 복원 데이터 모델이 필요해 효과 대비 우선순위 하향.
9야간 검토안 자동 준비수동 서버 운영 방침과 맞지 않고, 먼저 수동 검토 흐름의 가치를 검증해야 함.
