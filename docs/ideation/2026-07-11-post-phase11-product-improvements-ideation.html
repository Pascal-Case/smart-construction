Grounding Context

Codebase Context. 현재 대시보드는 연간 KPI와 차트, 링크 없는 최근 활동을 보여줍니다. 반면 작성 중·0원 매출, 확정 후 미발행, 종료 임박 계약, 이관 후 매출 미생성처럼 실제 조치가 필요한 데이터는 계약·매출·월별·명세표 화면에 흩어져 있습니다.

스마트 입력은 안전한 preview-first 구조를 이미 갖췄지만 단일 문장·단일 품목 중심이고, 분석 결과에서 현장·품목 이외의 수량·기간·금액은 바로 교정하기 어렵습니다. 주요 목록 필터는 로컬 상태라 새로고침·뒤로가기·공유 시 사라지며, 매출 상태 변경은 주로 단건 처리입니다.

외부 사례도 같은 방향을 지지합니다. TrackWIP과 Autodesk Construction IQ는 현금·위험 영향에 따라 조치를 우선순위화합니다. Linear와 Business Central은 동적으로 갱신되는 저장 뷰를 운영 자산으로 사용하며, Metabase는 결과가 있을 때만 알리는 방식으로 소음을 줄입니다.

핵심 판단: 이 제품의 다음 단계는 “더 많은 보고서”보다 “예외를 찾아 바로 처리하는 흐름”입니다.

1

오늘의 마감 데스크

대시보드·조치 큐신뢰도 94%복잡도 Medium

Description: 첫 화면의 중심을 연간 차트에서 “오늘 처리하면 청구·현금화가 진행되는 예외”로 옮깁니다. 작성 중·0원 매출, 확정됐지만 미발행, 종료 임박 계약, 이관 후 매출 미생성을 영향 금액·경과일·마감 임박도 순으로 보여주고 클릭하면 해당 필터가 적용된 작업 화면으로 이동합니다. 정상 항목은 표시하지 않아 조용한 날에는 화면도 조용합니다.

분산된 상태 데이터금액·기한·차단 단계 계산오늘의 우선 조치처리 화면 딥링크
Axis
대시보드와 조치 큐
Basis
direct: 기존 대시보드는 연간 집계 중심이지만 필요한 상태 데이터는 이미 여러 API에 존재합니다. external: TrackWIP·Autodesk의 cash-impact 우선순위, Metabase의 result-only alert 패턴과 일치합니다.
Rationale
사용자가 여러 화면을 돌아다니며 누락을 찾는 시간을 줄이고 대시보드를 매일 여는 업무 시작점으로 만듭니다.
Downsides
“중요도” 기준을 잘못 정하면 사용자가 큐를 신뢰하지 않습니다. 첫 버전은 설명 가능한 규칙과 수동 정렬을 제공해야 합니다.
Best first cut
작성 중·0원·미발행 세 가지 큐와 기존 목록 딥링크만 먼저 제공.
2

스마트 입력 2.0: 다건 초안 인박스

스마트·텍스트 입력신뢰도 92%복잡도 High

Description: 스마트 입력을 단건 폼 보조 기능에서 “메신저·회의 메모·여러 줄 텍스트를 안전한 업무 초안으로 바꾸는 인박스”로 확장합니다. 원문과 추출 필드를 나란히 보여주고 수량·단가·총액·기간까지 바로 교정하며, 선택한 초안만 저장합니다. 반복 교정 표현은 자동 반영하지 않고 관리자 승인형 별칭 후보로 축적합니다.

여러 줄 원문 붙여넣기계약·매출 초안 분리원문 대조·필드 교정선택 저장·별칭 후보
Axis
스마트·텍스트 입력
Basis
direct: 현재 단일 textarea, 텍스트 수정 시 preview 초기화, 현장·품목만 가능한 교정 표면이 명확한 마찰입니다. reasoned: 기존 preview-first 원칙을 유지하면서 입력 단위를 “한 문장”에서 “검토 가능한 초안 묶음”으로 확장할 수 있습니다.
Rationale
실제 업무 언어를 시스템 폼에 맞춰 다시 타이핑하는 시간을 줄이면서 자동 저장으로 인한 금액 오류는 방지합니다.
Downsides
다품목·다문장 분리 규칙과 편집 UI가 커집니다. 한 번에 모두 만들기보다 필드 직접 교정 → 여러 줄 분리 → 별칭 피드백 순으로 확장하는 편이 안전합니다.
Best first cut
기존 preview 카드에서 수량·단가·총액·기간 직접 수정과 재계산부터 제공.
3

월마감 워크벤치

목록·업무 흐름신뢰도 90%복잡도 High

Description: 월별 현황을 읽기 전용 표에서 단계형 마감 흐름으로 바꿉니다. 계약상 예상 매출과 실제 생성·확정·발행 금액을 대사하고, 작성 중·0원·예외단가를 점검한 뒤 안전한 일괄 확정과 명세표 발행까지 연결합니다. 각 단계의 남은 건수와 차단 사유가 0이 되어야 “마감 가능”으로 표시합니다.

예상 vs 실제 대사예외 점검안전한 일괄 확정명세표 발행·완료
Axis
목록·필터·일괄 처리
Basis
direct: 계약 생성 preview, 월별 집계, 원장 상태, 명세표 후보·발행은 이미 존재하지만 서로 분리돼 있습니다. 계획의 월 단위 확정·다중 처리도 현재 UI에는 완성되지 않았습니다.
Rationale
숙련자의 머릿속 체크리스트를 제품 흐름으로 고정해 담당자가 바뀌어도 동일한 품질로 마감하게 합니다.
Downsides
여러 도메인을 연결하므로 테스트 범위가 큽니다. 마감 “상태”를 별도 저장할지, 계산 결과로만 표현할지 먼저 결정해야 합니다.
Best first cut
월별 화면에 예상·생성·확정·발행 금액 대사표와 예외 딥링크만 추가.
4

업무 렌즈: 저장·공유되는 동적 뷰

내비게이션·개인화신뢰도 88%복잡도 Medium

Description: 계약·매출·월별·명세표의 필터와 정렬을 URL에 담고 이름을 붙여 개인 또는 팀 뷰로 저장합니다. “이번 달 미확정”, “송도 미발행”, “종료 30일 이내 계약”처럼 시간이 지나도 자동 갱신되는 뷰를 사이드바나 대시보드에 고정하고 링크로 공유합니다.

Axis
내비게이션·개인화
Basis
direct: 주요 목록 필터는 로컬 상태라 조건이 보존되지 않지만 감사·인쇄 화면에는 URL 기반 선례가 있습니다. external: Linear·Business Central의 saved dynamic views와 직접 대응합니다.
Rationale
매일 반복하는 필터 조합을 개인 노하우로 버리지 않고 팀이 공유할 수 있는 운영 자산으로 만듭니다.
Downsides
초기부터 개인/팀 권한, 대시보드 핀, 상세 서랍까지 모두 넣으면 범위가 커집니다.
Best first cut
URL search params 동기화와 “현재 조건 링크 복사”부터 시작한 뒤 이름 저장을 추가.
5

Git staging식 안전 일괄 처리

목록·일괄 처리신뢰도 91%복잡도 Medium

Description: 여러 매출을 선택해 즉시 확정·취소하는 대신 먼저 작업 바구니에 담고, 변경 전후 diff와 `처리 가능·이미 변경됨·보호됨·오류` 분류를 확인한 후 한 번에 실행합니다. commit 직전에 각 행의 version을 재검증해 충돌 행만 제외하거나 전체 취소할 수 있게 합니다.

Axis
목록·필터·일괄 처리
Basis
direct: import의 preview→commit, 명세표의 ID 배열 선택, 레코드별 version 충돌 제어가 이미 있어 공통 안전 계약을 만들 기반이 있습니다.
Rationale
월말 수십 건의 반복 클릭을 줄이면서 “대량 작업은 위험하다”는 운영 불안을 낮춥니다.
Downsides
월마감 워크벤치와 일부 겹칩니다. 먼저 독립적인 공통 bulk-action 계약으로 만들면 이후 마감 흐름이 이를 재사용할 수 있습니다.
Best first cut
매출 다중 확정만 지원하고, preview에서 충돌·불가 사유를 표시.

Rejection Summary

#검토한 아이디어제외·통합 이유
1모바일 현장 포착 루프모바일 입력 빈도와 오프라인 수요의 직접 근거가 없어 투자 우선순위 보류.
2전역 업무 실행기현재 내비게이션 실패 근거가 약하고 업무 렌즈와 상당 부분 중복.
3차트 없는 3문장 대시보드오늘의 마감 데스크에 통합. “3문장”은 유용한 표현 실험이지 제품 방향은 아님.
4결과형 예외 알림오늘의 마감 데스크에 앱 내 카드로 통합. 외부 알림은 운영 복잡도 대비 이른 단계.
5별칭 건강도·원문 대조 편집각각 독립 기능보다 스마트 입력 2.0의 구성 요소로 묶는 편이 강함.
6회계 대사·마감 체크리스트월마감 워크벤치의 핵심 구조로 통합.
7최근 활동 대신 중단한 곳부터가치는 있으나 사용자별 작업 복원 데이터 모델이 필요해 효과 대비 우선순위 하향.
8야간 검토안 자동 준비수동 서버 운영 방침과 맞지 않고, 먼저 수동 마감 흐름의 가치를 검증해야 함.
